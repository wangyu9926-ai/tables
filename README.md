# 牧马人线上多维表（通用引擎版）

**可复用的多维表格引擎**，不是某个业务的专用页面。设计参考 `mt_*` 多维表，独立前缀 `kb_`，
可以与其它应用共用一个 MySQL 库而互不干扰（不动对方的表）。
引擎本身不带数据：空库起步，项目 / 表 / 列和数据都由使用方自己建或导入（见「全新部署（空库起步）」）。

## 启动

- **本机带登录（默认 HTTPS）**：双击 `启动看板-带登录.bat`（或 `python auth_gate/run_gate.py`）→
  `https://127.0.0.1:8614`（局域网用本机 IP，如 `https://<本机局域网IP>:8614`）
  - 首次启动自动生成自签证书到 `auth_gate/certs/`（1 天前生效、10 年有效，SAN 含 localhost、主机名和本机所有 IPv4）。
    浏览器第一次访问会提示「证书不受信任」，选「继续访问」即可；**本机 IP 变了以后删掉 `auth_gate/certs/` 重启**，会按新 IP 重新生成。
  - 明文 HTTP 在 8614 上会被直接拒绝；改了证书目录可用 `GATE_CERT_DIR`。
  - 想回到明文 HTTP（仅限本机临时调试）：`GATE_SSL=0`。
- 云端 / 平台已经终结 TLS 时用 `GATE_HTTPS=1`：保持明文 HTTP，不生成证书。
- 其他可调环境变量：`GATE_HOST`（默认 0.0.0.0）、`GATE_PORT`（默认 8614）、`GATE_OPEN_BROWSER=0`（不自动开浏览器）。
- **数据库口令不再写在代码里**：优先读环境变量 `MUMA_DB_PASSWORD`，否则读 `backend/local.secrets.json`
  （已在 .gitignore 里，不要提交或外发）；两处都没有会启动失败并给出明确提示。
- 仅本机调试：`python run.py` 默认**拒绝启动**（它跳过登录网关，且是明文、免登录的）；确实要用必须显式设
  `KB_ALLOW_NOAUTH=1`，且它只绑 127.0.0.1，不要对外。

- 后端：FastAPI（`backend/app.py` = API，`backend/engine.py` = 引擎层）
- 数据库：MySQL 5.7+/8.0（utf8mb4），连接配置在 `backend/db.py`，可用 `MUMA_DB_*` 环境变量覆盖；口令不写在代码里
- 前端：`frontend/index.html`（纯静态，无构建）

## 全新部署（空库起步）

本仓库只有代码，**不含任何数据库快照或业务数据**（`migration/*.json`、`migration/*.sql.gz` 都在 `.gitignore` 里，
不会随代码分发）。从零部署是**空库起步**，没有任何示例数据：

1. **准备数据库**：MySQL 5.7+/8.0（utf8mb4）。可以先建一个空库，也可以在下面第 3 步让向导自动建。
2. **配连接（二选一）**：环境变量 `MUMA_DB_HOST` / `MUMA_DB_PORT` / `MUMA_DB_USER` / `MUMA_DB_PASSWORD` / `MUMA_DB_NAME`，
   或者什么都不配、直接走第 3 步的向导（它会写进 `backend/local.secrets.json`，该文件不进仓库）。
   建议给应用单独建一个最小权限的数据库账号，不要用 root。
3. **首次启动**（双击 `启动看板-带登录.bat`）：窗口里会依次问
   - **数据库**：地址 / 端口 / 用户名 / 口令 / 库名 —— 当场连一次，连不上会提示重填；库不存在可选自动创建；
     填好写进 `backend/local.secrets.json`（已 gitignore）
   - **管理员**：账号（默认 `admin`）+ 密码（两次确认，≥6 位）
   然后自动创建全部 `kb_*` 表、建好管理员并启动服务。**已经配好的部署完全跳过这一步**，不会打扰。
   后台/计划任务这类非交互启动不会等待输入：没有配置就打印环境变量清单后退出；
   也可以用 `GATE_ADMIN_PASSWORD` 预置管理员密码（仅在没有管理员时生效）。
4. **开始建内容**：登录 → 新建项目 → 新建表/列（字段类型：文本/数字/日期/单选/多选/勾选/公式/图片），
   或用表页「导入」上传 xlsx / xlsm / csv（支持列映射与类型），也可以走 `POST /api/in/{表ID}` 用写入密钥灌数据。
5. 空库时侧栏「仪表盘」也是空的，用表页「分析」自己建；汇总同步、批注、视图等都要在有了自己的表之后才有内容。

## 安全（登录网关 / 权限 / 内容安全策略）

- **登录网关**：独立账号体系（`kb_user` / `kb_perm`），中间件在应用之外先拦一道：未登录访问 `/` 只返回登录页，
  `/api/*` 一律 401（唯一例外 `POST /api/in/{表ID}`，凭表级写入密钥自校验）。
- **口令**：scrypt 单向加密；改密或被管理员重置后，已签发的旧登录凭证立即失效（`kb_user.token_ver`）。
- **Cookie**：`HttpOnly + SameSite=Lax`，HTTPS 下再加 `Secure`，有效期 12 小时。
- **登录限流**：同一 IP+账号 5 次失败锁 120 秒；同一 IP 20 次锁 10 分钟；**同一账号换 IP 连续猜 15 次锁 60 秒**
  （`GATE_USER_FAIL_LOCK` 可调），防止拿一个账号轮换 IP 慢慢猜。
- **跨站写保护**：浏览器发出的写请求必须来自本站（优先看 `Sec-Fetch-Site`，老浏览器退回比较 `Origin` 与 `Host`）；
  请求体只解析 `application/json`（文本/表单类的跨源请求不需要预检就能发出去，一律不认）。
- **请求体上限** 25MB（`GATE_MAX_BODY_MB`）；超出的导入直接拒绝。
- **内容安全策略（CSP）**：不放开 `unsafe-inline`。页面里每段内联脚本按 sha256 放行，页面里多出任何脚本都不会执行。
  - ⚠️ **按钮事件必须写在脚本里**（`addEventListener` / `el.onclick = fn`），**不能写 `onclick="..."` 这种标签属性** ——
    那种写法会被策略拦掉，表现是「按钮点了没反应、页面也不报错」。回归里有专门用例检查三个页面。
  - 万一改出问题，`KB_CSP_UNSAFE_INLINE=1` 一键退回旧行为；引擎里也有兜底：检测到标签内联事件/`javascript:` 链接时，
    该页面自动退回旧行为并在控制台打警告，不会把页面拦成白屏。
  - 其余响应头：`X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`frame-ancestors 'none'`、
    `base-uri 'self'`、`form-action 'self'`。
- **权限**：项目级 / 表级（viewer 只读、editor 可编辑），同时存在取更高的那个；字段管理、账号管理是「能力下发」。
  **导入可以用表头新建一张表（项目编辑者以上），但不能靠导入给现有表自动加字段**（那等于改表结构，需要字段管理能力）。
  关联数据接口要求双方表都有读权限；导出/预览/公式试算等接口都按目标表校验权限。
- **共用一台电脑**：本地缓存（表结构、上次看到的位置和筛选条件）按账号分开存，退出登录时清空；
  离开页面前（退出登录/会话失效）先清空已画出的数据；页面从浏览器「后退缓存」被恢复时强制重新加载 ——
  下一位登录或按后退都看不到上一位的内容。
- **资源上限**（防止一条数据把服务拖死）：单元格文本 20000 字、单选选项 500 字、多选 200 个、图片单元格 2000 字、
  公式表达式 4000 字；`REGEXEXTRACT` 的正则长度、匹配串长度和重复次数都有上限（Python 的 `re` 没有超时，
  灾难性回溯会把整个进程卡住）。
- **导出 CSV 防公式注入**：以 `= + - @` 开头的文本前面加 `'`，用 Excel 打开不会被当公式执行。
- **写入密钥**只存 sha256，明文只在生成时显示一次，可随时作废。

## 多人并发与性能

远程云数据库每次往返约 20~80ms，所以并发优化集中在「少查库、少重复计算」：

- **连接池有界**：默认 16 条长连接（`MUMA_DB_POOL` 可调），超过上限排队等连接，不会在并发高峰无限新建连接、反复做 TCP/认证握手。
- **登录态/权限缓存**：账号核验缓存 1.5 秒（`GATE_ACCOUNT_CACHE_TTL`），项目/表授权缓存 8 秒；账号增删改、授权变更时同进程立即清空，停用/收回权限最迟 1.5 秒生效。
- **鉴权查询不堵事件循环**：每个请求的账号核验放到线程池执行，登录的 scrypt 校验也放线程池；100 人同时打开页面/登录时不会一个接一个排队。
- **元信息单飞重建**：`/api/meta` 首次构建后内存直出，多个请求同时刷新也只查一次库；新增/删除行只更新该表计数，不重建全部表的元信息。
- **单元格编辑只失效本表**：更新一行直接改服务端行缓存，不再清空所有表缓存；把 JSON 转对象、筛选选项统计（facets）按表缓存，翻页/搜索/排序复用；行增删才失效该表视图。
- **改一格只重建本表的跨表索引**：其他表的索引照常复用；索引刚失效时多人同时打开，只重建一次（单飞）。实测：改一格后读公式表约 60~80ms（原来约 150ms）。
- **接口写入只影响目标表**：RPA / 脚本走 `POST /api/in/{表ID}` 写入后，只失效这一张表的缓存并补上行数，别人的页面不会被连带变冷。实测：写入后别人读别的表约 11ms（原来约 200ms）。
- **审计异步批量落库**：单元格保存不再等一条远程 `INSERT+COMMIT`；后台每 250ms 或攒 50 条批量写入，打开变动历史前会先 flush，读得到刚发生的操作。
- **乐观锁**：同一行多人同时改，后提交者收到 409「这行已被别人改过」，不会静默覆盖；不同行互不阻塞。
- **前端大页虚拟滚动**：每页 300 行时只渲染可视区上下各 10 行缓冲（约 30~35 行），其余用占位行撑高度；DOM 从 8700 个单元格降到约 1000 个，本机渲染 54ms→13ms、布局 137ms→10ms，滚动时换窗口。50/100 行小页仍一次性渲染。
- **单元格保存乐观更新**：输入回车后先用新值替换单元格、立即关掉输入框，再后台 PATCH；失败才回滚并提示，远程库往返期间不再干等。
- **预取收窄**：只预取当前分组的 2~4 张相邻 Sheet（300 行页只取 2 张），不再一开首页就把所有表全拉一遍。
- **首页静态化 + 协商缓存**：`/` 的原始/压缩内容、ETag、CSP 头按 (mtime,size) 缓存，内容没变回 304（0 字节、约 2ms）；
  压缩结果预先生成，不再每个请求现场 gzip。
- **`/api/meta` 按视图缓存**：管理员一份、游客一份、每个账号按「权限代次」各一份，直接返回缓存的 JSON 字节；
  授权/账号/表结构变化时只让相关视图失效。实测 0.8ms/请求（原来约 17ms）。
- **行接口直接复用序列化结果**：列表/筛选/分页结果按请求参数缓存为 JSON 字节，命中时不再逐行 json.dumps。
- **前端行缓存**：切 Sheet / 切表先用上次结果秒开再后台对齐；结构变化清全部，某张表行变了只清这一张（预取的其它 Sheet 不受影响）。
- **跨表等待只等自己的总表**：只有「被汇总规则指向的表」在打开时才等同步队列（最多 1.5 秒），读别的表完全不受子表写入影响。

**40~50 人**：同时打开页面 p50 约 0.2~0.3 秒，日常使用很宽裕。
**100 人**：同时打开/刷新约 0.5~1.3 秒；100 人同时保存不同行约 1 秒完成；100 人同时登录约 4 秒（只在早上集中登录时遇到）。空闲用户不轮询、不占连接，100 人在线但分散操作时后端压力很小。
**边界**：同一行多人同时改仍按乐观锁走 409；当前是单进程，100 人以上持续高频写（不是偶发高峰）建议再加进程/Redis 共享缓存或读写分离。

## 数据模型（引擎核心）

| 表 | 作用 |
|---|---|
| `kb_table` | 表定义：name / note / group_name / icon / sort（**任意建表改表删表**） |
| `kb_column` | 列定义：key / label / type / options / **option_colors** / **expr** / width / sort / required / hidden |
| `kb_row` | 行数据：JSON + ver 乐观锁 + 软删 |
| `kb_audit` | 变动历史：谁/何时/哪行哪字段 旧值→新值 |
| `kb_relation` | 表间关联（保留的表结构；行尾 🔗 入口已移除，暂无 UI 使用） |
| `kb_dashboard` | 项目级数据分析看板：名称 / 图表配置 JSON / `is_page`（是否发布到侧栏）/ 创建人 |
| `kb_image` | 图片单元格文件：table_id / mime / size / LONGBLOB / 创建人 |
| `kb_comment` | 单元格批注：table_id / row_id / col_key / 正文 / 作者 / 时间；软删，作者或管理员可删 |
| `kb_apikey` | HTTP 写入密钥：table_id / key_hash(sha256) / key_prefix / note / revoked；明文只在生成时显示一次 |
| `kb_setting` | 系统设置（键值）：目前只记「默认授权已初始化」这一个标记 |

**列类型**：text / number / date / select / multiselect / checkbox / image / **formula**

**胶囊配色**：单选/多选字段渲染为胶囊。钉钉导出的 xlsx 已剥离所有填充色与条件格式，
颜色无法从文件读出，因此按 11 色冷暖交替调色板分配（浅天青蓝/浅杏奶橘黄/淡薰衣草紫/
浅桃粉/薄荷浅绿/浅焦糖棕/浅灰蓝/浅鹅黄/灰调青灰/豆沙浅红/浅灰紫）：同列内按选项顺序
轮转，列与列起始色不同；已发布/已合作/已建联/建联中/待定/拒绝等状态保留语义色。
人员字段（负责人/跟进人）与自由文本字段不画胶囊。

## 公式列（本项目相对参考项目新增的能力）

- 列类型选 **公式**，写表达式，用 `{列名}` 引用同行字段
- 运算符：`+ - * / %`、幂 `^`、文本连接 `&`；比较 `= != <> > >= < <=`
  （Excel 风格单等号 `=` 也认，字符串比较不区分大小写）；支持 `AND OR NOT` 与嵌套 IF
- **空值语义**：空字段参与算术按 0、参与比较一律 False、`ISBLANK({列})` 判空；
  除以 0 返回空，可用 `IFERROR(表达式, 兜底值)` 捕获
- 函数清单（大小写不限）：
  - 数学：`ROUND ROUNDUP ROUNDDOWN ABS MAX MIN SUM AVERAGE MOD POWER SQRT INT CEIL FLOOR`
  - 逻辑：`IF IFERROR AND OR NOT TRUE FALSE ISBLANK ISNUMBER ISTEXT`
  - 文本：`CONCAT CONCATENATE LEN LEFT RIGHT MID TRIM UPPER LOWER SUBSTITUTE FIND REGEXEXTRACT REPT`
    （`REGEXEXTRACT(文本, 正则)` 取第一个匹配；正则长度 ≤200、只匹配前 2000 字符、重复次数 ≤10，防灾难性回溯；
    `REPT` 结果封顶 20000 字符）
  - 日期：`TODAY NOW YEAR MONTH DAY DATE DAYS DATEDIF WEEKDAY`
- 后端 **AST 白名单求值**（不用 eval，不执行任意代码），只读、不落库；表达式最长 4000 字符
- **文本参与算术按出错处理**（文本 + 文本仍是直接拼接）：`文本 * 数字` 这类写法不再尝试拼一个巨大的字符串
- 行保存接口、关联数据接口返回的行里也带公式计算值（跨表公式同样有值）：改一格不会让同行的跨表列变空，
  改的正好是被匹配字段本身时，引用本表的 COUNTIF 也按改后的数据算
- 公式列可引用其他公式列（按列顺序依次计算）
- **可引用同项目其他表**（LOOKUP/汇总）：
  `LOOKUP("达人建联表-抖音·Sheet1","账号昵称",{达人昵称},"进度")`
  `SUMIF("达人建联表-抖音·Sheet1","账号昵称",{达人昵称},"粉丝数")`
  `COUNTIF("表名","对方匹配字段",{本表字段})` / `AVGIF` / `MAXIF` / `MINIF`
  表名用双引号写 `kb_table.name`（组·Sheet），按匹配字段相等的行取值/汇总；跨表只允许同项目。
  **表/分组改名会自动同步公式里写死的表名引用**。
  字段编辑器里有「引用其他表」构建器：选表 → 对方匹配字段 = 本表字段 → 取值字段 → 处理方式 → 插入。
- 前端字段管理里编辑公式时**实时试算**，建列时后端校验引用列存在 + 语法。
  试算接口只对该表有字段管理权限的人开放（必须带表 ID）；**非管理员写的公式，跨表函数只能引用自己有权读的表**。
- 样例：迁移后「达人数据看板-抖音·Sheet1」自带公式列
  `千次互动成本 = ROUND({合作金额}/IF({总互动}=0,1,{总互动})*1000,2)`
- 常用组合示例：
  `发布天数 = DAYS(TODAY(),{实际发布时间})`
  `达标 = IF(AND({粉丝数}>=10000,{当前阶段}="已发布"),"达标","未达标")`
  `文案 = CONCAT({达人昵称},"（",{粉丝数},"粉）")`

## 视图与操作习惯

- **你的视图 vs 大家的表**：搜索、筛选、排序、列宽、页签/侧栏顺序都是**你自己的**，存在本机（按账号），不进表结构；
  别人打开同一张表看到的是他自己的视图。真正共享的是表结构：列、隐藏列、汇总规则、看板——那些由有权限的人在字段管理/表设置里改。
- **「重置」按钮**：工具栏搜索框旁边，只有在你搜索/筛选/排序过之后才出现，点一下回到默认视图（页码也回第一页），有提示。
  手机上在「更多」菜单里（`重置视图（清除搜索/筛选/排序）`）。列宽恢复默认是双击表头右边界（和 Excel 一样）。
- **行数**：分页左侧常显「共 N 行」；有搜索/筛选时显示「筛选后 N 行（全部 M 行）」，避免“以为数据丢了”。
- **空状态**：表里真没数据时提示点「＋ 行」或用「导入」；被搜索/筛选挡住时明确说“没有符合条件的行、共 M 行被挡住”，并直接给一个清除按钮。
- **键盘**（表格软件习惯）：单击选中 → Enter/F2 编辑、直接打字开始改、← → 移动、Esc 取消；编辑中 Tab 提交并右移，Shift+Tab 左移。
- **撤销 / 重做**：Ctrl+Z / Ctrl+Y，撤销的是你自己刚改的单元格（批量粘贴算一条）；乐观锁兜底，别人改过的行不会被覆盖。
- **批量粘贴**：从 Excel 复制一片，点中起始格 Ctrl+V；只贴进当前页已有的行，未变化的格子跳过。
- **常用视图**：工具栏「视图 ▾」→「保存当前条件为视图…」，之后一键切换；默认视图 = 清空搜索/筛选/排序。只存本机、按表分开。
- **高级筛选**：任意一个筛选浮层底部「高级筛选：多列「且 / 或」…」→ 加条件、选且/或、应用；条件留空自动忽略，
  已删掉的列不会凭空把数据筛没。改了「且/或」或增删条件会重绘，已经填的值会保留；手机 390px 下条件行会自动折成两行。
- **右键菜单**：行上右键可上移/下移、插入、复制、删行；列头上右键可「按内容适应列宽」、恢复默认列宽、按此列排序。
- **拖动行**：按住行号拖动整行调整顺序（所有人可见，会写审计）；按列排序时先取消排序再拖。
- **批注**：选中格子的气泡按钮、格子右上角橙色角标、右键菜单都能打开；只读账号可写，作者/管理员可删。
- **实时刷新（服务器推送 + 轮询兜底，最小化重绘）**：页面开着某张表时挂一条 SSE 长连接（`GET /api/tables/{tid}/events`），
  有人写入就推「哪几行变了」，页面**只重画变的那几行**（`GET /api/tables/{tid}/rows/by-ids?ids=…` 只取这几行），
  其他行一个字节都不动、滚动位置不变；只有行集合变了（新增/删除/翻页/总数变化）才整页重绘。
  同事改完到上屏约 **100~200ms**（实测：取数 55ms + 15ms 合并等待），没变化就不发请求。
  推送只带变更提示、不带数据，所以不会把你没保存的输入冲掉；正在编辑的那一行不会被替换。
  正在编辑格子、行编辑侧栏开着、弹窗里在填表、删除/导入进行中时先攒着，手上的动作结束再刷新。
  自己刚保存触发的那条不再重复刷新；断线自动重连，彻底连不上（或浏览器不支持）就退回 5 秒一次的 `/changes?since=` 轮询。
  **并发**：两个人同时改同一格由服务端版本号裁决，后保存的会收到 409 提示（不会悄悄覆盖）；
  多个标签页/多个人各开各的连接，服务端只做广播，慢的客户端不会拖住别人。
- **切回页面自动刷新（兜底）**：从别的窗口/标签页切回来（窗口重新获得焦点）时也会静默重取当前页；
  4 秒内不重复请求。
- **共用电脑的本地缓存**：登录时只保留当前账号的本地视图缓存，别的账号遗留的（上一位没点退出就关浏览器）会顺手清掉。
- **视觉细节**：窄屏（约 1000~1280 带管理员按钮）工具栏会自动换行不再被裁掉；列头排序时整列头换底色并显示 ▲/▼；
  表头吸顶滚动后带阴影；行尾的「删除」平时淡显、悬停变实；键盘焦点有焦点环；首页项目卡片带图标和表数量；
  行详情标题显示主要字段值（行号放副标题），变动历史用「谁 · 时间 · 做了什么」的人话描述。

## 汇总同步（子表 → 总表）

- 入口：**总表**页顶栏「汇总同步」（仅 admin；手机在「更多」菜单）。
- 选同项目的一张子表，逐字段映射到总表字段；可点「来源表名（自动）」把子表名写进总表某一列。
- 单向镜像：子表**新增**行 → 总表追加；**修改** → 总表对应行更新；**删除** → 总表对应行软删。只复制字段原值，不做运算。
- 一个总表可以接多张子表；每张子表一条规则，互不影响。
- 首次保存会在后台把子表已有行全量复制过去，界面显示「同步中 x / y」；之后增量实时同步。
- 多条规则同时全量时**后台串行执行**（其余显示「排队中」），不会一起打满数据库连接拖慢前台。
- 增量同步走后台队列，**子表保存不等待总表写入**；打开总表时会先把已排队的增量做完再返回。
- 用 `kb_sync_link` 记录「子表行 → 总表行」，重复点「立即同步」只对账、**不会重复插入**。
- 删除规则会停止同步，并删除该子表已复制到总表的行（界面有确认）。
- 子表被删除时，会自动清掉它对应规则和已复制的总表行。
- 支持复制：文本 / 数字 / 日期 / 单选 / 多选 / 勾选。**公式列、图片列不复制**；总表自己的公式列会按复制后的值重新计算。
- **双向（2026-11-26 起）**：子表 → 总表照旧；反过来，在总表改一个**从子表汇总来的行**（`kb_sync_link` 里有链接的），
  改动的映射字段会**回写子表对应行**（子表行版本号 +1、记审计 `sync_back`），所以两边看到的是同一份数据。
  **总表直接新增的行没有链接，不会同步到子表**；在总表删除一个镜像行，子表对应行会一起软删（记 `sync_back_delete`）。
  冲突以**总表这次修改为准**（只回写你改的那几个字段，没动的不碰）；回写用内部标记防止「总表→子表→总表」来回打转。
- 仅支持同项目内汇总；不支持双向同步、定时同步、跨项目汇总。
- 实测：100 行首次全量约 4 秒；无变化的重复全量约 0.4 秒。
- 典型用法：把同结构的多张子表汇到一张总表，另加一列「来源表」（映射 `$source_table`）区分来源；
  总表自己的公式列按复制过来的值重算。**汇总规则不做去重**：如果子表之间本来就互为副本，会产生重复行，
  这种情况先把重复副本去掉（或用 `kb_sync_link` 把链接指向已有行）再开汇总。

## 数据分析

- 入口：任意表页顶栏「分析」，打开当前项目的看板；不会再开新标签页。
- 一个项目可建多个看板；看板配置存 `kb_dashboard.config`，团队共享。
- 顶栏「保存」把当前看板发布成侧栏「数据表」下面的分析页面（`is_page=1`）：
  首次保存会填页面名（默认「数据分析」），之后直接保存；侧栏入口点开即进入该分析页。
  未保存的看板只存在于「分析」入口，不会出现在侧栏；删除看板会同时移除侧栏入口。
- 图表类型：指标卡、柱状图、条形图、折线图、环形图、明细表。
- 指标：计数、去重计数、求和、平均、最小、最大；支持 1-4 个指标。
- 维度：文本 / 单选 / 多选 / 日期（按天/月/年）/ 数字 / 勾选；支持不分组。
- 筛选：包含、等于、不等于、数值区间、日期区间、为空、不为空等，按字段类型给控件。
- 数据直接复用行接口和前端缓存，选表后全量聚合；图表用手写 SVG，不依赖 CDN。
- 权限：分析页只跟随**项目级授权**，表级授权不单独放行。
  项目 viewer 能看（含侧栏已保存页面），项目 editor 才能建/改/删看板、图表和保存页面；
  游客不可见。viewer 的图表按表权限再过滤：表级 `none` 的图表不下发，整页没有可看图表时
  侧栏分析入口也隐藏；数据仍走每张表的权限校验。
- 数值解析兼容 `2万` / `1.2w` / `1.5亿` / 千分位；未发布行的 0 会参与计算，效果分析时建议加
  「当前阶段 = 已发布」筛选。
- 同一批数据如果被拆成多张表（如按页拆成 Sheet1~4），做汇总前先确认它们是否互为副本：
  汇总规则不会自动去重，重复的表汇到同一总表会产生重复行。

## Excel / CSV 导入

- 入口：任意表页顶栏「导入」；空项目页「导入 Excel」直接进入「新建一张表」模式，不需要先有表。
- 支持 `.xlsx` / `.xls` / `.xlsm` / `.csv`，单文件 ≤20MB、≤50000 行；表头默认第 1 行，可改。
- 先读预览：可选工作表、看行列数、看前 8 行；不会直接落库。
- 三种落库方式：
  - **追加到当前表**：按列映射写入现有字段；未匹配列可自动新建字段，也可手动忽略。
  - **覆盖当前表**：先软删当前表所有行再写入，失败自动回滚；导入前有确认。
  - **新建一张表**：用 Excel 表头建列，自动推断文本/数字/日期/单选/勾选，可在弹窗里改类型、取消列。
- 值处理：Excel 日期/时间转 `YYYY-MM-DD`；数字支持千分位与 `2万`/`1.2w`/`1.5亿`；多选按 `, ， ; ； 、 换行` 拆分；单选自动补充新选项；公式列和图片列不导入。
  单元格长度受上限约束（文本 20000 字、选项 500 字、多选 200 个），超出的值会被拒绝而不是悄悄截断。
- 权限：预览也要求对目标表（或目标项目）有权限——解析 Excel 是重活，不能只凭「已登录」就调用；
  追加/覆盖要求当前表可编辑；新建表要求项目可编辑。只读用户看不到「导入」按钮，接口也会 403。
  **项目编辑者可以靠导入新建一张表，但没有「字段管理」能力时，追加导入不能给现有表自动新建字段**
  （映射里不显示「新建字段」选项，多出来的列默认忽略）。
- 导入会写 `kb_audit`（导入 N 行 / 导入新建表），其他客户端下次读表即看到新数据。

## HTTP 写入（RPA / 脚本）

- 入口：任意表页顶栏「写入密钥」（管理员；手机端在「更多」里）。每张表独立密钥，可备注用途、随时作废。
- 生成时明文只显示一次，库里只存 sha256；弹窗里可直接复制密钥或整条 curl 命令。
- 免登录接口（密钥只对所属表有效，不能跨表用）：

  ```bash
  # 服务默认 HTTPS（自签证书），脚本里加 -k 跳过证书校验；换成局域网地址/云端地址同理
  curl -k -X POST https://127.0.0.1:8614/api/in/12 \
    -H "X-KB-Token: kbk_..." \
    -H "Content-Type: application/json" \
    -d '{"data": {"名称": "张三", "数量": 100}}'
  ```

  批量：`{"rows": [{...}, {...}]}`，单次 ≤1000 行；返回 `{"ok": true, "inserted": N, "ids": [...]}`。
- 字段名可写列 key 或显示名（如「名称」）；未知列和公式列自动忽略；必填列缺失整批拒绝并指出第几行。
- 数字支持 `2万` / `1.2w` / `1.5亿` / 千分位；日期支持 `YYYY-MM-DD`；多选可传数组或逗号分隔文本。
- 每次写入落一条 `api_insert` 变动历史，actor 为 `api:<密钥备注>`；密钥生成/作废也写审计。
- 安全边界：密钥是**表级写凭证**，不是登录态；只能插入，不能读数据、不能改列结构；作废立即生效。

- 新部署是空库起步，不需要任何历史迁移脚本：用表页「导入」上传 Excel/CSV，或走 `POST /api/in/{表ID}` 灌数据即可。

## 已知边界

- **证书是自签的**：第一次访问浏览器会提示不安全，选「继续访问」；本机 IP 变了要删 `auth_gate/certs/` 重启重新生成。
  要彻底消掉提示，可以把 `server.crt` 装进「受信任的根证书」，或用内网域名 + 正式证书（改 `GATE_CERT_DIR` 指向即可）。
- **数据库口令**不写在代码里（环境变量 / `backend/local.secrets.json`）。建议定期轮换，并给应用单独建一个
  最小权限的数据库账号（在数据库侧操作）；`backend/local.secrets.json` 不要提交或外发。
- 云端托管时客户端 IP 依赖平台代理传的 `X-Forwarded-For`（网关只在直连/内网对端时采信），具体平台是否原样透传未验证。
- **公式正则防卡死是「预检查 + 长度上限」**，不是真超时（Python 的 `re` 没有超时机制）：拦截了嵌套重复、可空重复、
  长重复次数等常见灾难性写法，输入串截断到 2000 字符、表达式 4000 字符；公式作者都是有编辑权限的内部用户。
- 登录/权限：独立账号表 kb_user + 授权表 kb_perm（项目级 / 表级 × 只读 / 可编辑）。
  **未登录一律只返回登录页**，项目/表/行/分析接口全部 401，不再有游客浏览
  （唯一例外：`POST /api/in/{表ID}` 凭表级 `X-KB-Token` 写入，见上文）；
  staff 只能看到被授权的项目/表，viewer 只读、editor 可改行。
  建表/删表/建 Sheet/项目增改删仍是 **admin 专属**；**列/字段管理**可由 admin 下发 `can_fields`，
  但只对该用户有编辑权的表生效；**账号管理**可下发 `can_users`，**列表只显示自己和自己新增的
  staff**，且只能新建/启停/重置自己权限范围内的账号，新建账号默认无授权，由创建者点「授权」
  在自身有效角色内分配只读/可编辑（不能授出比自己更高的角色），不能建管理员、改角色、
  操作带能力或非自己新增的账号；下发能力本身只有 admin 能设置（用户管理表格
  「字段管理/账号管理」两列点击切换），收回立即生效。
  入口：右上角「登录」，「用户管理」对 admin 或下发了账号管理能力的人可见；管理员仍可用 /__auth/admin 兜底。
  授权目录列出**所有项目（包括还没建表的空项目）**；项目改名会同步项目级授权，删项目会清掉该项目授权，后续同名重建不会继承旧权限。
  改密码、或被管理员重置密码后，已签发的旧登录凭证立即失效（`kb_user.token_ver`）。
  **默认授权是一次性初始化**：只在全新部署首次启动时给已有 staff 授予全部项目 editor，做完在 `kb_setting` 记 `perm_seed_done`，之后重启不再发放——管理员清空授权也不会被还原。
  **隐藏列只影响显示，不是权限控制**：有表权限的人仍能从行接口拿到隐藏列的值，敏感数据请用授权来隔离。
  字段管理里编辑列只改提交的字段，不会动原有的必填 / 隐藏 / 列宽。
- 公式支持同行字段引用和同项目跨表 LOOKUP/SUMIF/COUNTIF/AVGIF/MAXIF/MINIF；
  不支持跨行窗口函数或跨项目引用；表/分组改名会同步更新公式里写死的表名引用。
- HTTP 写入只有插入语义，不做 upsert / 去重；同一批数据重试会产生重复行，调用方需自备幂等判断。
- 行尾「关联数据」（🔗）**已按需求移除**：它原本只按 `kb_relation` 里显式配置的字段对做跨表匹配，但库里从来没有过配置、界面上也一直没有配置入口，
  点开永远是空的，所以干脆把入口删掉。后端 `GET /api/related` 和 `kb_relation` 表还在（仍做双方表的读权限校验），以后要重启这个能力再接 UI 即可。
- 导入不支持公式列、图片列；合并单元格只读左上角值，多级表头请先整理成单行表头。
- 图片单元格支持 png / jpg / gif / webp / bmp，单张 ≤8MB，存 MySQL `kb_image`；
  读取接口按表权限校验，游客和只读限制同样生效；清空单元格不会立即删库里的原图。
- 行数据存 JSON，单表几十万行内没压力；分析页当前在前端全量聚合，数据量再大时再下推服务端。
